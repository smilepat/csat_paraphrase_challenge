# 채점기 캘리브레이션 기록

`npm run calibrate` 로 재현. 데이터는 `data/calibration/set.json`.

## 무엇을 재는가

축을 하나씩만 움직인 데이터로 각 축을 따로 잰다. 총점 하나로 뭉뚱그려 재면
측정 도구 자체의 결함이 채점기 성능처럼 보인다(실제로 v1 에서 그럴 뻔했다).

| 계열 | 고정 | 변화 | 정답 라벨 |
|---|---|---|---|
| coverage | 길이 18-22단어, 쉬운 어휘 | 담은 명제 수 k = n..1 | 생성 시 지정한 `specCovered` |
| contradict | 길이·어휘 | 명제 0 을 정반대로 진술 | 구성상 모순 |
| ease | 의미·길이 | 어휘 난이도 4단계 | 지정 등급 |
| brevity | 의미·어휘 | 길이 15/25/35/48단어 | **실제** 단어 수 |
| verbatim | — | 원문 잘라내기 | 구성상 복붙 |

정답 라벨의 한계: 사람 교사의 판단이 아니라 **구성 사양 + 독립 심판 LLM 확인**이다
(생성 99건 중 심판과 사양이 어긋난 항목 0건). 채점기가 망가졌는지는 잡지만,
교사 감각과 일치하는지는 교사 검토가 따로 필요하다.

## 측정으로 밝혀진 것 (설계가 바뀐 이유)

### 1. 임베딩은 명제 커버리지를 재지 못한다

한 지문의 명제들은 서로 주제가 같다. 그래서 4개 중 1개만 담은 답안도 나머지
3개와 0.78+ 유사도를 보인다. 임베딩만 쓰면 커버리지 1.00 과 0.25 의 점수 차가
**50.0 vs 47.6 — 2.4점**에 불과하다. 임계값을 어떻게 잡아도 해결되지 않는다
(격자 탐색 최대 ρ 0.728).

→ 커버리지의 1차 판정은 **LLM 의 명제별 입장(agree/disagree/absent)**이 맡는다.
   임베딩은 LLM 이 꺼졌을 때(`PARAPHRASE_LLM=off`)의 폴백으로 남긴다.
   폴백 경로는 ρ 0.811 로 순서는 대체로 맞지만 **점수 간격이 거의 없다** —
   등수는 매길 수 있어도 절대 점수는 신뢰하지 말 것.

### 2. 임베딩 모델 선택이 의미 역전 탐지를 좌우한다

같은 문장쌍에 대해:

| 모델 | 올바른 패러프레이즈 | 의미 역전 | 간격 |
|---|---|---|---|
| `text-embedding-004` | (퇴역, 404) | — | — |
| `gemini-embedding-001` | 0.812 | 0.804 | **0.008 — 구별 불가** |
| `gemini-embedding-2` | 0.915 | 0.840 | 0.075 |

`gemini-embedding-2` / 768차원을 쓴다. 768 과 3072 의 성능 차는 무시할 만하고
저장량은 1/4 이다.

그래도 임베딩만으로는 역전을 못 막는다 → 모순 게이트는 LLM 필수.

### 3. "모순 명제 인덱스를 나열하라"는 물음은 약하다

첫 판정 프롬프트는 모순 탐지율 **67%** 였다. 명제마다 `agree/disagree/absent`
입장을 **강제로** 고르게 바꾸자 **100%** 가 됐다. 모델에게 목록을 만들게 하면
빈 배열로 넘어가기 쉽다.

### 4. 모순은 누락보다 무겁게 쳐야 한다

모순 명제를 0점 처리만 하면 "3개 담고 1개를 거꾸로 말한 답안"이 "3개만 담고
1개를 빠뜨린 답안"과 같은 점수가 된다(실측 42.5 vs 42.5 로 겹침). 모순 명제는
**-1** 로 계산한다. 그 결과 구간이 분리됐다(35.0 < 42.5).

### 5. 베낌 판정에 임베딩을 쓰면 안 된다

임베딩은 "같은 뜻"을 재므로, 같은 생각을 자기 말로 다르게 쓴 정직한 답안도
0.95 를 넘긴다. 그걸 부정행위로 몰면 이 게임이 장려하려는 행동을 처벌하게 된다.
베낌은 표면 문제이므로 **최장 공통 연속 단어 + 내용어 자카드**로 잰다.
실측 오탐 0/84.

## 캘리브레이션이 재지 않는 것 — 점수 곡선 (2026-08-20)

여기 적힌 수치는 **판정의 정확도**(의미 갈래·재표현 여부·모순·복붙)를 잰 것이다.
판정 결과를 몇 점으로 환산하는지는 **재지 않는다.**

그래서 유형 1 의 회피 감점 방식을 바꿀 때(§50: 비율 → 남긴 낱말 개수)
이 문서의 수치는 다시 돌릴 필요가 없었다. 반대로 프롬프트·모델·임계값을
건드리면 여기부터 다시 돌려야 한다.

**점수 곡선을 바꿀 때 확인할 것**은 따로 있다:
`scripts/simulate-learners.mjs` 가 같은 계수를 쓰는지(안 그러면 킬 기준이
배포된 채점과 다른 세상을 잰다), 그리고 승인 문항 전체에서 대표 답안의
점수가 어떻게 움직이는지.

## 임계값을 다시 잡아야 할 때

- 임베딩 모델을 바꿨을 때 (유사도 분포가 통째로 이동한다)
- 지문 유형을 넓혔을 때 (도표·안내문 등은 명제 구조가 다르다)
- `npm run calibrate -- --sweep` 으로 의미 축 격자 탐색 후
  `lib/scoring/config.ts` 의 `MEANING` 수정

## 라이브 확인 (실제 API)

`npx vite-node scripts/live-check.mjs` — 실제 Gemini 로 한 라운드를 채점하고
호출 수와 캐시 동작을 센다. 답안 픽스처는 선택된 지문에 맞춰 그 자리에서 생성한다
(하드코딩하면 다른 지문에서 주제부터 어긋나 무의미해진다 — 실제로 처음에 그랬다).

2026-07-27 결과 (CSAT_2015_18, 명제 5개, 목표 25단어):

| 답안 유형 | 총점 | 의미 | 간결 | 쉬움 | 플래그 |
|---|---|---|---|---|---|
| 좋은 요약 | 93.0 | 50 / 50 | 25 | 18.0 | — |
| 부분만 | 64.8 | 26 | 25 | 13.8 | — |
| 의미 역전 | 62.8 | 20 | 25 | 17.8 | contradiction |
| 원문 복붙 | 69.3 | 26 | 25 | 18.3 | verbatim, peer-copy |
| 너무 김 | 54.2 | 35.9 | 0 | 18.3 | verbatim |

한국어 피드백도 정확했다("핵심 주장을 반대로 이해했어요", "모든 핵심 주장을 잘 요약했어요").

**비용**: 5명 라운드에 3콜(임베딩 2 + 판정 1). 30명이면 임베딩 1~2 + 판정 3 = **약 5콜**.
같은 답안 재채점은 **0콜**(캐시 적중 확인).

**복붙 점수 처리 (2026-07-27 변경)**: 원문 복붙의 원점수는 69.3 으로 여전히 높게
나온다. 임베딩·규칙만 보면 실제로 "핵심을 다 담은 짧은 글"이기 때문이다.
문제는 그게 순위표 1~2위에 오른다는 것이었다.

자동으로 0점 처리하지는 않는다 — 정당한 인용을 기계가 가려낼 수 없다.
대신 **판단 전까지 어디에도 반영하지 않는다**(`lib/rooms.ts` 의 `reviewState`):

| 상태 | 조건 | 순위·팀점수·평균 | 학생 화면 |
|---|---|---|---|
| `counted` | 플래그 없음, 또는 교사 인정 | 반영 | 점수 표시 |
| `pending` | 플래그 있음 + 교사 미확인 | **제외** | "선생님이 확인 중입니다" |
| `rejected` | 교사 기각 | 제외 | "점수에 반영되지 않았습니다" |

교사가 확인을 건너뛰면 그 제출은 그냥 집계에서 빠집니다 — 높은 점수가 남는 것보다
낫다고 판단했다. E2E 가 이 동작을 검증한다(복붙 제출이 베스트 3 에 없고, 명단에
"확인 대기"로 뜨고, 기각 후 학생 화면에 반영 제외가 표시되는지).
